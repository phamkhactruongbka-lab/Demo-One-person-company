# Route work through Naruto

Convert the request into one outcome and a reviewable task brief. Naruto remains the single intake and coordinator; specialist departments contribute bounded deliverables.

## Workflow

1. Preserve the requested outcome and identify missing facts that materially affect scope. Continue independent work while stating reasonable assumptions.
2. Write the scope, exclusions, deliverables, acceptance criteria, deadline, priority, owner, dependencies, and known blockers.
3. Assign only the departments needed, up to five. Give each a concrete output and handoff condition; avoid duplicate ownership.
4. Order work by dependency, define the next checkpoint, and raise blockers with the decision needed from Founder.
5. Send the completed brief to Kakashi for independent acceptance review. Keep unverified work in review; never label a draft as delivered or approved.

## Guardrails

- Do not invent approval, external results, deadlines, or evidence.
- Keep spending, account access, publication, outreach, and production release behind the required Founder decision.
- Report status from artifacts and observed task records, not role-played chat.
